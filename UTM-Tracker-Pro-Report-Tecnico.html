1. Panoramica del prodotto

UTM Tracker Pro è una web app SaaS in italiano per agenzie e professionisti del marketing che gestiscono campagne pubblicitarie multi-cliente. La piattaforma consente di costruire link UTM standardizzati, raggruppare i tracciamenti per cliente, generare URL brevi tracciabili e visualizzare analytics in tempo reale (click totali, click 7gg, andamento, top link).

Funzionalità chiave rilevate dall'interfaccia pubblica:
  • Wizard guidato per la creazione di link UTM (Cliente → Canale → Conferma)
  • Gestione clienti (CRUD)
  • Short link redirect tramite endpoint /r/[code]
  • Dashboard con metriche: Click Totali, Click Oggi, Click 7gg, Link Attivi, picco e media, andamento click, top link cliccati
  • Pagina di analytics dettagliata per singolo link /analytics/[id]
  • Autenticazione interna con registrazione "agenti" (Nome, Cognome, Email, Username, Password, Area/Zona)
  • Sezione amministrativa /users

3.3 Middleware

Un middleware Next.js da 27.1 kB intercetta tutte le richieste in entrata. È responsabile, con altissima probabilità, di:

  • Lettura del cookie di sessione e validazione del JWT
  • Redirect di utenti non autenticati verso /login
  • Gating delle aree protette (/dashboard, /clients, /create, /links, /users, /analytics)
  • Possibile inoltro del traffico /r/[code] verso il logger di click prima del redirect

5. Sicurezza & networking

  • HTTPS forzato con strict-transport-security: max-age=63072000; includeSubDomains; preload
  • Edge cache Vercel attiva (x-vercel-cache: HIT) sulle pagine statiche
  • Rewrite caching abilitato (x-vercel-enable-rewrite-caching: 1)
  • Vary headers su RSC, Next-Router-State-Tree, Next-Router-Prefetch per la corretta cache dei React Server Components
  • CORS aperto (access-control-allow-origin: *) sulle pagine pubbliche; le API protette ereditano il check del middleware
  • Auth custom via cookie httpOnly (nessuna esposizione di token al client JavaScript)

7. Conclusioni

UTM Tracker Pro è un'applicazione Next.js 14 ben strutturata che sfrutta in modo idiomatico l'App Router per separare aree pubbliche statiche, dashboard dinamiche e API serverless. Le scelte architetturali — autenticazione custom con middleware, region singola iad1, build cache attiva, mix statico/dinamico — sono coerenti con un MVP SaaS già in produzione su Vercel.

Punti di forza tecnici: bundle leggero, prerendering aggressivo dove possibile, separazione netta tra logica server (API + middleware) e UI client, animazioni fluide con framer-motion.

Aree di possibile evoluzione: aggiunta di region multi-zona per ridurre la latenza in Europa, edge runtime per /r/[code] al fine di velocizzare il redirect, introduzione di un sistema di analytics più granulare (es. integrazione Vercel Analytics o piattaforme dedicate).
